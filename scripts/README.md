# Data Migration Scripts

This directory contains scripts for Phase 1 of the data migration process from Sanity to HuggingFace format.

## Scripts Overview

### 1. `export-from-sanity.ts`
Exports all content types from Sanity with resolved references.

**Features:**
- Exports all 8 content types: products, categories, groups, apptypes, applications, tags, guides, settings
- Resolves all references (category, tags, guides, etc.)
- Handles localized fields with proper language fallback
- Converts Sanity `_id` to clean `id` format
- Includes comprehensive logging and error handling

**Usage:**
```bash
pnpm tsx scripts/export-from-sanity.ts
```

**Output:**
- `exports/` directory with individual JSON files for each content type
- `exports/combined.json` with all data combined
- Each file includes metadata (export timestamp, record count)

### 2. `transform-to-hf.ts`
Transforms exported Sanity data to HuggingFace JSONL format with flat locale fields.

**Features:**
- Converts Sanity `_id` to clean `id` format (e.g., "prod-001")
- Flattens localized fields: `desc.en` → `desc_en`
- Converts references: `category._ref` → `category_id`
- Transforms Portable Text to simplified JSON
- Sorts data by type and ID for consistency
- Generates comprehensive metadata

**Usage:**
```bash
pnpm tsx scripts/transform-to-hf.ts
```

**Output:**
- `hf-output/data.jsonl` - JSONL format file with all transformed data
- `hf-output/metadata.json` - Transformation metadata and schema information

### 3. `migrate-images.ts`
Migrates images from Sanity CDN to R2 storage.

**Features:**
- Extracts image URLs from exported data
- Downloads images from Sanity CDN
- Uploads images to Cloudflare R2 storage
- Updates image URLs in transformed data
- Generates image metadata and backup copies

**Environment Variables Required:**
```bash
CLOUDFLARE_ACCOUNT_ID=your_account_id
CLOUDFLARE_ACCESS_KEY_ID=your_access_key_id
CLOUDFLARE_SECRET_ACCESS_KEY=your_secret_access_key
CLOUDFLARE_R2_BUCKET=your_bucket_name
CLOUDFLARE_R2_ENDPOINT=https://your-account.r2.cloudflarestorage.com
```

**Usage:**
```bash
pnpm tsx scripts/migrate-images.ts
```

**Output:**
- `migrated-images/` directory with local image backups
- `migrated-images/image-metadata.json` - Image migration metadata
- `hf-output/data-with-updated-images.jsonl` - Data with updated image URLs

## Execution Order

1. **Export from Sanity:** `pnpm tsx scripts/export-from-sanity.ts`
2. **Transform to HuggingFace:** `pnpm tsx scripts/transform-to-hf.ts`
3. **Migrate Images:** `pnpm tsx scripts/migrate-images.ts`

## Data Types

### Exported Types (Sanity Format)
- `ExportedProduct` - Product data with resolved references
- `ExportedCategory` - Category data with group reference
- `ExportedGroup` - Group data with embedded categories
- `ExportedAppType` - Application type data
- `ExportedApplication` - Application data with type references
- `ExportedTag` - Tag data
- `ExportedGuide` - Guide data
- `ExportedSettings` - Settings data

### HuggingFace Types (Transformed Format)
- `HFProduct` - Product with flat fields and resolved references
- `HFCategory` - Category with flat fields and group reference
- `HFGroup` - Group with embedded category arrays
- `HFAppType` - Application type with flat fields
- `HFApplication` - Application with type reference arrays
- `HFTag` - Tag with flat fields
- `HFGuide` - Guide with flat fields
- `HFSettings` - Settings with flat fields

## Error Handling

All scripts include comprehensive error handling:
- Try-catch blocks around critical operations
- Detailed logging with timestamps
- Graceful failure with meaningful error messages
- Progress tracking for large datasets

## Logging

Each script provides detailed logging:
- `[INFO]` - General information and progress updates
- `[WARN]` - Non-critical issues that don't stop execution
- `[ERROR]` - Critical errors that terminate execution

## Dependencies

The scripts require:
- `next-sanity` - Sanity client
- `groq` - GROQ query language
- `tsx` - TypeScript execution
- Node.js built-in modules (fs, path, crypto)

## Development Notes

- Scripts are designed to be run sequentially
- Each script can be run independently for testing
- The transform script requires the export script to have been run first
- The image migration script requires the transform script to have been run first
- All scripts include TypeScript types for better development experience
